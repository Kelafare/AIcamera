## 1. 项目概述

### 1.1 产品定位

「漫镜头」是一款手机端 AI 相机应用。用户在素材库中新建「角色文档」，上传自己喜欢的二次元角色图片；取景时选择一个角色，把角色以贴合现场光影、透视和遮挡的方式叠加到真实场景里，形成「二次元角色站在真实世界中」的预览，并可拍照留存。

产品的核心不是单张图片的生成质量，而是「角色在真实场景里是否可信」：

- 角色不闪烁、不脱位、不穿帮；
- 遮挡、尺度、光影、接地关系可信；
- 用户能理解并接受 AI 生成的节奏。

整图逐帧重绘会让成本随秒数膨胀、画面闪烁、推理跟不上帧率。因此方案坚持：

- **背景不重绘**：背景逐像素取自相机原始帧，只生成角色图层；
- **事件驱动生成**：只在需要时生成新贴图，不按固定帧率生成；
- **显式 AI 模式**：本地相机实时取景，用户主动进入 AI 渲染，延迟被隔离在 AI 模式内；
- **WYSIWYG 快门**：用户看到什么就拍什么。

### 1.2 两段式体验

```
[首页]
  │ 开始拍照
  ▼
[本地相机]  ← 实时、纯本地、无上传、无 AI 叠加
  │ 用户站稳 + 点「开始 AI 渲染」
  ▼
[AI 预热]   ← 开始上传；本地画面继续 + 「AI 显影中，请保持不动」
  │ 首帧就绪（约 10s，目标自适应 3–5s）
  ▼
[AI 稳定预览]  ← 延迟画面；允许缓慢前后左右移动/旋转
  │ 剧烈抖动 / 锚点出画 / 需要新贴图
  ▼
[花屏遮罩]  ← 前 2s 轻花屏，之后平静「显影中」+ 进度
  │ 严格平稳（仅手抖级）+ 新贴图就绪
  ▼
[AI 稳定预览]（恢复，延迟照旧）
  │ 按快门
  ▼
[捕获/最终渲染]  ← 冻结用户看到的帧；二次生图 + 光影协调
  ▼
[图片预览]  ← 保存 / 放弃
  ▼
[本地相机]  ← AI 关闭；可继续构图，或再次进入 AI
  │ 返回
  ▼
[首页]
```

关键点：

- 本地相机是**默认相机界面**，实时、无延迟、不上传。用户走动、找角度、构图都不受 AI 影响。
- 10 秒延迟只存在于用户**主动进入**的 AI 模式里；用户被明确告知延迟，UI 持续显示。
- 拍照确认后回到**本地相机**，不是首页；减少往返，适合连续拍摄。
- 再次进入 AI 会开启新会话，需要新的预热；本地相机本身不需要等待。

### 1.3 关键决策摘要

| 决策 | 定稿选择 | 理由 |
|---|---|---|
| 预览架构 | 云端延迟渲染（MVP）；端侧合成作为量产备选 | 画面内部自洽、客户端瘦；代价是带宽/延迟 |
| 延迟 | 默认 10s，目标自适应 3–5s | 用户可接受「AI 显影」；缓冲覆盖生成/网络波动 |
| 快门 | WYSIWYG，抓用户看到的预览帧 | 所见即所得，避免构图错位 |
| 角色素材 | 角色文档文件夹 + 自动清洗 + 角色卡 | 用户零负担，不要求分类 |
| 站位/姿势 | 服务端 AI 导演自动提案 + 「换一个」 | 相信模型审美，同时保留兜底 |
| 姿势控制 | AI 生成的姿势条件，不是姿态库 | 保留「全部由 AI 生成」的体验 |
| 遮挡 | 合成器按深度/分割 mask 处理 | 几何问题交给合成器，稳定可控 |
| 最终成片 | 二次生图 + 光影协调 + 风格/背景闸门 | 预览分辨率不够；成片要更自然，但保持二次元画风 |
| 拍照后 | 回到本地相机 | 减少回首页往返 |

### 2.1 状态机

```
                                                ▼

                                            │          ▲
                     剧烈抖动 / 锚点出画 /  │          │ 严格平稳 + 新贴图就绪
                     需要新贴图              ▼          │
                                         [AIFaultMask]─┘
                                            │ 按快门
                                            ▼
                                         [Capture]
                                            │
                                            ▼
                                      [FinalRender]
                                            │
                                            ▼
                                       [PhotoReview]
                                            │ 保存/放弃
                                            ▼
                                        [LocalCamera]  ← AI 关闭
                                            │ 返回
                                            ▼
                                          [Home]
```

### 2.2 各阶段说明

**本地相机**

- 实时预览、无 AI 叠加、无上传、无网络依赖。
- 手机本地 IMU + 帧差计算稳定度；稳定后启用「开始 AI 渲染」。
- 本地相机可作为普通相机使用；用户也可以直接点「开始 AI 渲染」进入 AI 模式。

**AI 预热**

- 用户点「开始 AI 渲染」后才开始上传，并提示「画面将上传云端处理、AI 预览约有延迟」。
- 本地画面继续显示，叠加「AI 显影中，请保持不动」的进度/倒计时。
- 首次生成在预热期间完成；预热时长约等于播放缓冲时长。
- 如果实际生成 p95 是 1.5–3 秒，预热/缓冲可以压到 3–5 秒。

**AI 稳定预览**

- 显示服务端渲染的延迟视频流；每帧带采集时间戳。
- 允许相机缓慢前后左右移动和旋转；旧锚点在安全边界内、角度未超过重绘阈值时，不触发遮罩或重新生成。
- 锚点锁定、复用优先；角色位置不会每帧跳动。

**花屏遮罩**

- 触发条件：运动等级达到剧烈抖动；锚点移出安全边界；角度超过重绘阈值或触发超时刷新。
- 遮罩分两段：前 2 秒轻花屏（半透明撕裂、轻微色偏、细颗粒），之后转为平静的「显影中」+ 进度；避免用户盯着花屏 10 秒。
- 遮罩期间用户仍能看清构图；花屏不是错误提示，是体验保护层。

**恢复**

- 手机本地判定严格平稳（仅手抖级扰动），且服务端新贴图就绪。
- 手机标记可生成帧，服务端生成并合成到对应时间戳；恢复时淡入/交叉淡化。
- 只要仍存在可观测的平移、旋转或前后位移，就不提前恢复。

**拍照与回顾**

- 快门抓取当前显示帧的时间戳；服务端从缓冲取出该帧及元数据。
- 冻结画面 + 显影/渲染进度；最终渲染完成后进入图片预览页。
- 保存写入相册/应用内图库；放弃删除临时结果；两种情况都回到本地相机。

### 2.3 双时间 UI

```
┌─────────────────────────────┐
│                             │
│   主画面：延迟 10s 的 AI 合成  │
│   （魔法镜 / 显影中）          │
│                             │
│  ┌─────────┐  稳定度 ●●●○    │
│  │ 实时小窗 │  锚点：正常      │
│  │（当前）  │  延迟：10s       │
│  └─────────┘                │
└─────────────────────────────┘
```

- 主画面是延迟 AI 预览；角落实时小窗显示当前相机画面。
- 稳定度、锚点状态、延迟时长由手机本地计算/显示，实时更新。
- 目的：10 秒延迟下，用户仍能知道自己「现在稳不稳、锚点在不在、还要等多久」，而不是所有反馈都晚 10 秒。
- 可选：首次引导解释「AI 显影」节奏；持续延迟标识，而不是一次性弹窗。

### 2.4 延迟与缓冲

延迟由四部分组成：

```
端到端延迟 = 采集编码 + 上行 + 服务端排队/处理 + 下行 + 解码 + 播放缓冲
```

缓冲吸收的是「波动」，不是「平均值」：

```
buffer ≈ max(网络抖动 p95 + 0.5s, 服务端处理波动 p95 + 0.5s)
如果要求新视角贴图无缝插入：buffer ≥ 生成 p95 + 0.5s
```

| 场景 | 网络抖动 p95 | 处理波动 p95 | 生成 p95 | 建议缓冲 | 体验 |
|---|---|---|---|---|---|
| 同局域网/好 Wi-Fi，服务端稳定，生成异步 | 0.05–0.1s | 0.1s | 1.5–2s | 2–3s | 轻微延迟 |
| 普通 4G/公网，服务端一般 | 0.2–0.5s | 0.2–0.3s | 2–3s | 3–4s | 明显延迟但可用 |
| 弱网/服务端排队 | 0.5–1s | 0.5s | 3–5s | 5–6s | 需要「延迟预览」提示 |
| 固定 10s | — | — | — | 10s | 明显「看到过去」，只适合摆拍 |

原则：

- 网络本身不需要 10 秒；720p30 在 5G/Wi-Fi 上单向延迟通常 20–80ms，抖动 50–200ms；1–2 秒缓冲足够。
- 真正的大头是生成；生成 p95 1.5–3 秒时，3–4 秒缓冲就能覆盖。
- 10 秒是 MVP 的保守默认值，不是必需值；目标自适应到 3–5 秒。
- 弱网优先降码率/降分辨率，而不是堆缓冲；缓冲不能解决服务端过载。
- 拍照走单独的帧路径，不受预览缓冲影响；缓冲越小，快门按下的帧越新。

## 3. 角色素材库

### 3.1 角色文档

- 用户在素材库新建「角色文档」（一个文件夹），随意上传角色图片。
- 不要求用户分正面/侧面/背面，也不要求填写详细分类。
- 使用时选择一个角色文档（和可选的 look），AI 用文档里的图片做身份参考。

```
素材库
 └─ 角色文档「小樱」
     ├─ 参考图：用户上传的各种图片
     ├─ 角色信息：名字、身高、性格标签、描述
     ├─ 形象（look）：默认 / 校服 / 战斗服
     └─ 生成记录 / 缓存（可选）
```

### 3.2 自动清洗与角色卡

```
用户丢一堆图
   │
   ▼
质量过滤（模糊/低清/水印/NSFW/重复）
   │
   ▼
角色检测 + 裁剪 + 去背景
   │
   ▼
去重 + 聚类（多角色/多服装）
   │
   ▼
选最佳参考图（清晰/正脸/全身/多样）
   │
   ▼
身份 embedding + VLM 描述 +（可选 LoRA）
   │
   ▼
角色卡（AI 的理解，用户可改可不改）
```

- 系统自动筛掉糊图、截图、表情包、重复图；识别角色主体；去背景；选参考图。
- 如果文件夹里混了多个角色/多套服装，系统聚类，给用户一个轻量选择（「这是哪个角色？」/「用哪套衣服？」）。
- 角色卡示例：

```
角色卡「小樱」
  AI 识别：粉发、绿眼、校服；主要参考 6 张
  可选：编辑名字/标签、删掉不合适的图、补充全身/背面
```

- 用户丢完图就能用；角色卡只是让用户知道「AI 理解成了什么」，可以改，但不改也能跑。
- 角色卡也是运行时 VLM 的输入：性格标签（害羞/元气）会影响它选什么姿势。

### 3.3 身份与参考图

- 多图参考比单图更能保住身份；IP-Adapter 使用多张参考图（或拼图/多图适配器）。
- 图多时可选训练每角色 LoRA，进一步提升身份一致性；用户不管理训练过程。
- 没有全身/背面图时，模型会脑补；角色卡上给可选提示「补一张全身/背面会更稳」，但不强制；必要时限制环绕角度。
- 多套服装聚类成 look；用户选，或让 AI 按场景选。

### 3.4 内容审核与权利

- 上传图片和生成结果都做内容审核。
- 用户需确认拥有角色素材的使用权。
- 角色素材可能涉及版权；条款与审核是上线门槛，不是附录。

## 4. AI 导演

### 4.1 目标

让 AI 不只是「画师」，而是「导演」：

- 看懂场景，决定角色站在哪里、摆什么姿势最自然；
- 在满足硬约束的候选里，按审美排序；
- 用户默认接受模型的选择，但可以「换一个」；
- 生成、遮挡、光影、质检分别由合适的模块负责，而不是让一个模型一次搞定所有事。

### 4.2 候选提案

- VLM 看当前场景 + 角色卡，提出 2–3 个「站位 + 姿势」候选，每个候选带简短 caption。
- 候选硬约束（不能交给审美）：
  - 角色位于可行承载面（地面/桌面/床面/台阶）；
  - 脚底贴地、尺度合理；
  - 脸/上半身可见；
  - 不穿模、不悬空；
  - 不贴边（有意构图如「探头」除外）。
- 审美排序交给 VLM：在满足硬约束的候选里选最自然/最有意思的。
- 默认展示最佳候选；用户可「换一个」切预生成的备选。

### 4.3 姿势条件：AI 生成，不是姿态库

- 用户侧没有姿态库；姿势由 AI 生成。
- 技术上有「姿势条件」来保证稳定，但它是 AI 生成或从角色文档里取的，不是用户可见的库：
  - VLM 用自然语言描述姿势（「从柱子左侧探头，脸在 (x,y)，一只手扶柱子」）；
  - 生成一张姿势参考图或粗骨架；
  - 或直接用角色文档里用户上传的某张图做姿势参考。
- 如果完全不要姿势条件，纯 prompt 也能跑，但「探头/坐/靠」等姿势和遮挡稳定性会差一些，需要更多候选 + 质检 + 重试。
- v1 建议先用「VLM 描述 + 生成姿势参考图」这个轻量条件，它不是姿态库，但能显著提高稳定性。

### 4.4 生成与遮挡合成

- 角色生成：角色文档多图 IP-Adapter（图多时可选 LoRA）保身份；ControlNet 保姿势；场景深度/分割保空间关系；inpainting 限定角色区域。
- 遮挡由合成器负责，不交给生成模型：
  - 生成完整角色；
  - 用柱子/前景的深度/分割 mask 把被挡住的部分扣掉；
  - 在遮挡边缘加 AO/接触阴影；
  - 保留可见的脸/手部。
- 例子：柱子后探头

```
场景：一根柱子
1. VLM：柱子左侧可以探头；脸在 (x,y)；身体在柱子后。
2. 姿势条件：生成「探头」姿势参考图/骨架。
3. 生成：角色文档参考 + IP-Adapter + 姿势条件 + 深度 → 完整角色。
4. 合成：柱子 mask 把身体后半部分扣掉；柱子边缘加 AO/接触阴影。
5. 质检：脸可见、身份像、姿势自然 → 通过。
```

- 这是**静态姿势**，不是动画。角色不会自己动，但姿势可以是「探头」。这与初稿「角色不会抬手/转身」的边界一致。

### 4.5 质量闸门与锚点

- 质量闸门检查：
  - 身份相似度；
  - 脸可见面积；
  - 脚底接地；
  - 姿势自然度；
  - 画风一致性（二次元 vs 写实）；
  - 伪影（多余肢体、悬空、穿插）。
- 不合格候选不展示为默认结果；尝试下一个候选或重试。
- 锚点选定后锁定；缓慢移动期间复用，不每帧重新选择；只有锚点失效、用户明确更换或遮罩恢复时才重新选择。
- 跨视角一致性：没有姿态条件时，转动相机容易让「探头」变成「站着」；需要姿势条件、视角图集或 3D proxy 来锁住姿势。这个条件可以是 AI 生成的，用户不用管。

## 5. AI 预览与延迟

### 5.1 云端渲染 vs 端侧合成

| 维度 | A. 全云端渲染（定稿 MVP） | B. 端侧合成 + 云端生成（初稿 2.2） |
|---|---|---|
| 手机做什么 | 采集、编码、上传、解码、显示；本地感知 | 采集、跟踪、合成、显示；上传静帧 |
| 服务器做什么 | 解码、VLM、深度/分割、生成、合成、编码 | 深度/分割/生成；回传贴图+蒙版 |
| 上下行带宽 | 双向持续视频流，约 2–4 Mbps/用户 | 事件静帧+贴图，平均约 0.1–0.4 Mbps/用户 |
| 端到端延迟 | 处理+网络+播放缓冲，约 5–10s | 背景实时；角色召唤约 1.5–3s |
| 画面自洽性 | 高：贴图合成在生成它的那一帧上 | 中：贴图需 warp 到当前帧，有跟踪误差 |
| 服务器 GPU | 每帧合成/编码 + 生成 | 仅生成（+可选深度/分割） |
| 手机复杂度 | 低（瘦客户端） | 中（原生渲染/AR） |
| 弱网/离线 | 差 | 较好（已有贴图可推演数秒） |
| 隐私 | 持续上传视频 | 仅生成时上传静帧 |
| 成本 | 高（带宽+GPU） | 低（事件驱动） |

- **MVP 选择 A**：协议简单、客户端瘦、画面自洽；适合快速验证「角色站在真实世界里」的观感。
- **量产备选 B**：带宽/成本低一个量级，背景实时，弱网可用；但需要原生跟踪/合成。
- **中间态**：A 的基础上，让手机跑 AR 并把 pose/plane 发给服务端，服务端只跑生成和渲染，不跑跟踪；省服务端 CV 成本，也提高稳定性。

### 5.2 状态机

见 2.1。关键规则：

- 稳定预览允许缓慢移动/旋转；旧锚点在安全边界内、角度未超阈值时不触发遮罩。
- 遮罩触发：剧烈抖动、锚点出画、角度超阈值/超时刷新。
- 恢复：严格平稳 + 新贴图就绪；手机本地判定，服务端生成并合成到对应时间戳。
- 锚点变化时淡入，避免硬切。
- 会话结束（保存/放弃/退出）停止上传、释放服务端资源、清理缓冲。

### 5.3 双时间 UI

见 2.3。核心是「主画面延迟、状态实时」：手机本地 IMU/AR/光流负责稳定度和锚点感知，服务端只负责重生成与渲染。

### 5.4 缓冲与传输

- 上下行都传 H.265 编码帧，不传原始 YUV；10 秒编码帧约 2–5MB/用户。
- 服务端保留输入帧、渲染输出帧和每帧元数据（锚点、姿势、贴图版本），支持按时间戳回溯。
- 手机播放缓冲 + 服务端输入抖动缓冲 + 生成余量；默认 10 秒，目标自适应 3–5 秒。
- 时间戳贯穿采集、上传、处理、回传、播放；快门按显示帧时间戳取图。
- 服务端每帧处理必须快于实时（建议 GPU 硬编硬解），否则缓冲会被耗尽。
- 生成任务与每帧合成/编码分开调度，生成不能阻塞实时渲染线程。

### 5.5 降级与异常

降级链（从轻到重）：

1. 复用旧贴图，暂停新生成；
2. 降低回传码率/分辨率；
3. 关闭逐像素遮挡，只保留整体合成；
4. 回退本地相机，提示用户稍后重试。

其他规则：

- 遮罩期间不能提前恢复；只要仍存在可观测的平移、旋转或前后位移，就保持遮罩。
- 服务端过载/排队时优先降级，而不是无限增大缓冲。
- 会话结束清理帧、元数据和临时生成结果。

## 6. 拍照与最终渲染

### 6.1 WYSIWYG 快门

- 快门捕获当前显示帧的时间戳，发给服务端。
- 服务端从缓冲取出该帧及其元数据（锚点、姿势、贴图版本）。
- 照片对应用户按下快门时看到的画面；即使该帧是 10 秒前的延迟帧，也按该时间戳回溯。
- 快门后冻结画面 + 显影/渲染进度；用户知道拍到的是哪一刻。

### 6.2 最终渲染管线

最终渲染不是在预览贴图上简单放大，而是一次独立的「二次生图 + 光影协调」：

```
捕获帧（WYSIWYG）
  │
  ├─ 1. 二次生图：角色文档参考 + 当前姿势条件 + 场景深度/上下文
  │      → 在角色区域重新生成高分辨率角色
  │
  ├─ 2. 合成：角色 + 阴影 mask 合成到捕获帧；mask 外背景像素级保留
  │
  ├─ 3. 光影协调：场景光照/色温估计 → 低频光照/色彩匹配 + 边缘光
  │      → 接触阴影/AO + 边缘 matting/羽化
  │
  ├─ 4. 风格保持：二次元特化模型 + IP-Adapter + ControlNet(lineart/pose/depth)
  │      → 角色 mask 内低-中去噪；不做写实重绘
  │
  └─ 5. 质量闸门：身份/脸可见/背景保真/画风一致性/伪影
         → 通过：输出成片
         → 失败：回退捕获帧或保守色彩匹配版本
```

**能保证什么**

- **真实背景**：mask 外背景像素级不变（硬保证）；质量闸门检查 SSIM/LPIPS。
- **二次元画风**：用二次元特化模型 + lineart 条件 + 低-中去噪；质量闸门做画风一致性检查；不通过则回退。不是 100% 每个像素的保证，但产品级可控。
- **不劣化**：最终渲染失败/超时/闸门不通过时，回退到用户捕获的预览帧，不会丢照片或给更差的结果。

**不能保证什么**

- 复杂光照、玻璃/镜面、动态物体、极端遮挡下的「完美自然」；v1 明确不支持或降低预期。
- 二次元角色与现实背景的「完全无缝」；产品追求的是「可信的二次元角色站在真实世界里」，不是写实合成。

### 6.3 可选高清重拍

- 默认 WYSIWYG 输出预览分辨率（720p/1080p）。
- 可选「高清重拍」：用当前高分辨率 still + 高分辨率角色生成更高分辨率照片。
- 该选项必须显式；不影响默认 WYSIWYG 路径；需说明与预览构图可能略有差异。

### 6.4 保存/放弃

- 保存写入相册/应用内图库；放弃删除临时结果。
- 两种情况都回到**本地相机**（AI 关闭），不是首页。
- 用户可以直接继续构图，或再次点「开始 AI 渲染」进入新的 AI 会话。

## 7. 技术架构

### 7.1 端云职责

```
Phone                                 Server
┌──────────────────────┐              ┌──────────────────────────────┐
│ LocalCamera          │              │ Ingress / Decode             │
│  · realtime preview  │              │  ├─ VLM scene analysis       │
│  · no upload         │              │  ├─ Character profile load   │
│  · IMU stability     │              │  ├─ Depth / Segmentation     │
│  · anchor/pose sense │              │  ├─ AI pose condition        │
│  · "Start AI" button │              │  ├─ Character generation     │
└──────────┬───────────┘              │  ├─ Occlusion compositing    │
           │ video + metadata         │  ├─ Quality gate             │
           ▼                          │  ├─ Encode / Egress          │
┌──────────────────────┐   rendered   │  └─ Frame/metadata buffer    │
│ AI session           │◀─────────────│                              │
│  · decode / display  │   stream     │                              │
│  · live thumbnail    │              │                              │
│  · WYSIWYG shutter   │   photo      │                              │
│  · final render wait │◀─────────────│  Final render                │
│  · photo review      │              │                              │
└──────────────────────┘              └──────────────────────────────┘
```

**手机**：相机采集/编码/上传/解码/显示；本地 IMU/AR/光流做稳定度、锚点位置、角度阈值判断；实时小窗；快门时间戳；图片预览。

**服务端**：流接入/解码；VLM 场景分析与候选；角色文档加载；深度/分割；姿势条件；角色生成；遮挡/阴影合成；质量闸门；编码回传；帧与元数据缓冲；最终渲染。

手机不上传本地相机阶段的画面；只有用户点「开始 AI 渲染」后才开始上传。

### 7.2 云端服务

- **接入/解码**：H.265 流接入、鉴权、限流、解码。
- **VLM 场景分析**：看场景 + 角色卡，提出站位/姿势候选。
- **角色文档服务**：加载参考图、身份 embedding、角色卡、可选 look。
- **深度/分割**：Depth-Anything-V2 类单目深度 + 可行承载面分割；可按机型/成本选择端侧或云端。
- **姿势条件**：VLM 描述 + 生成姿势参考图/骨架。
- **角色生成**：IP-Adapter（可选 LoRA）+ ControlNet + inpainting。
- **遮挡合成**：深度/分割 mask + AO/接触阴影 + 边缘融合。
- **质量闸门**：身份/脸可见/接地/自然度/画风/伪影。
- **编码/回传**：H.265 编码 + 时间戳。
- **缓冲**：输入帧、渲染输出帧、每帧元数据。
- **最终渲染**：二次生图 + 光影协调 + 风格/背景闸门。

部署注意：

- 生成服务按单请求低延迟配置；动态批处理对生成意义有限。
- 模型常驻显存；切换角色不应触发主模型重载。
- 量化分模型对待：生成 FP16/FP8；深度 INT8；光流对数值精度敏感。
- 生成任务与实时渲染线程分开调度。
- GPU 常驻池/预热；生成 p95 与容量规划要单独做。

### 7.3 AR 作为可选传感器

- AR 不等于 3D 建模。ARCore/ARKit 提供相机 pose、平面、深度、光照；角色仍然是 2D 贴图/sprite，不需要 3D 模型。
- 手机端可用 AR 获取 pose/plane/depth/light，作为元数据随视频流发送；服务端用这些元数据放置角色、做遮挡与光照匹配。
- 没有 AR 时回退到 CV：光流 + 单目深度 + 平面分割。
- 中国区 Android 可能没有 GMS/ARCore；必须有 CV 回退。
- AR 不能解决角色本体的 3D 视差；绕到侧面/背面仍需视角重生成或限制轨道。

### 7.4 数据模型

```
CharacterDocument
  id, name, tags[], description
  referenceImages[]      # 原始上传图
  selectedReferences[]   # 自动选出的最佳参考
  identityEmbedding       # IP-Adapter / CLIP / face embedding
  looks[]                 # 服装/形态聚类
  heightCm                # 尺度参考，可选
  card                    # AI 识别到的外观/标签（用户可改）
  cache                   # 可选视角图集/生成记录

AISession
  id, characterDocumentId, lookId
  state                   # LocalCamera/AIWarmup/Stable/FaultMask/Capture/Review
  buffer                  # 时间戳 -> 帧/元数据
  anchor                  # 3D/2D 锚点、平面、深度
  posePlan                # VLM 提案：姿势描述、姿势条件、caption
  candidates[]            # 预生成的备选
  qualityGate             # 身份/脸可见/接地/自然度分数

FrameMetadata
  timestamp, cameraIntrinsics, cameraPose
  anchor, depthRef, segmentationRef
  textureVersion, posePlanId

Photo
  displayTimestamp, sourceFrame
  finalRender, resolution
  savedAt / discardedAt
```

### 7.5 性能与成本

- **端侧**：本地相机 + 编码/解码/显示；本地感知（IMU/光流）控制在毫秒级；重活都在服务端。
- **生成 p95**：决定缓冲和体验。1.5–3s 时 3–5s 缓冲够用；5–10s 时 10s 缓冲是合理临时值，量产要优化。
- **带宽**：云端渲染双向视频流约 2–4 Mbps/用户；设备合成方案可低一个量级。
- **GPU**：每帧合成/编码 + 事件驱动生成；需要常驻池、排队、优先级、降级。
- **成本**：按 GPU 型号/利用率/生成频率算；事件驱动 + 会话制 + WYSIWYG 预览分辨率是成本控制的关键。
- **热/电**：手机本地只做轻量感知；按温度降级（降分辨率、降感知频率、关逐像素遮挡）。

### 7.6 隐私、安全、合规

- 本地相机阶段不上传；进入 AI 会话时明确提示「画面将上传云端处理」。
- 服务端只在会话期间保留帧与元数据；会话结束清理。
- 角色素材和生成结果做内容审核；用户确认素材使用权。
- 角色素材可能涉及版权；条款、审核、投诉渠道是上线门槛。
- 传输加密；访问控制；防滥用/额度。

## 8. MVP 范围与非目标

### 8.1 MVP 范围

- 两段式流程：本地相机 → AI 会话 → 拍照 → 图片预览 → 本地相机。
- 角色素材库：角色文档文件夹、零负担上传、自动清洗/聚类、角色卡。
- AI 导演：VLM 候选、硬约束、AI 姿势条件、生成、遮挡合成、质量闸门、「换一个」。
- AI 预览：预热、延迟预览、稳定/遮罩/恢复状态机、锚点锁定、双时间 UI。
- 拍照：WYSIWYG 快门、冻结帧、最终渲染（二次生图 + 光影协调 + 风格/背景闸门）、保存/放弃。
- 基础隐私提示、内容审核、权利确认。
- 真机性能/成本基线；灰度/回滚开关。

### 8.2 非目标

- 角色自主动画（抬手、转身、走动）；v1 只做静态姿势。
- 全程走动式实时 AI 预览；延迟取景只存在于 AI 会话内。
- 没有背面参考图时的 360° 环绕一致性；默认限制 ±90° 或接受脑补。
- 动态物体遮挡、玻璃/镜面/大面积反光的正确处理。
- 视频录制；v1 只做照片。
- 默认高分辨率成片；高清重拍作为可选。
- 用户可见的姿态库或手动摆姿；姿势由 AI 生成。
- 多角色同框、复杂群像。

### 8.3 假设

- 目标设备至少能稳定跑本地相机 + 硬件编解码；中端机为目标下限。
- 用户能接受「AI 显影」的延迟节奏，并被明确告知。
- 服务端有可用 GPU 池；生成 p95 在可接受范围。
- 角色素材由用户提供，平台有基本审核与条款。

## 9. 风险与开放问题

### 9.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 10s 延迟用户不接受 | 体验/留存 | AI 模式隔离、明确告知、双时间 UI、目标自适应 3–5s |
| AI 自动站位不可靠 | 10s 白等 | 硬约束 + 2–3 候选 + 「换一个」+ 质量闸门 + 安全回退 |
| 姿势漂移/跨视角不一致 | 角色「换人」/变姿势 | AI 姿势条件 + 质量闸门 + 视角图集/3D proxy |
| 角色文件夹太杂 | 身份/质量差 | 自动清洗/聚类/角色卡；低质提示不阻塞 |
| 最终二次生图身份/画风漂移 | 成片不像角色 | 多图参考 + lineart + 低-中去噪 + 风格闸门 + 回退 |
| 分辨率不够 | 成片糊 | 默认 WYSIWYG + 可选高清重拍 |
| 云端带宽/GPU 成本高 | 单位经济 | 会话制、事件驱动、自适应码率、降级链 |
| 服务端过载/排队 | 延迟/卡顿 | 常驻池、优先级、每用户频率限制、降级 |
| 隐私/版权/审核 | 上线门槛 | 本地优先、显式同意、会话清理、审核与条款 |
| 动态物体/玻璃/镜面 | 穿帮 | v1 明确不支持，引导场景选择 |
| 手机发热/耗电 | 体验 | 本地只做轻量感知，按温度降级 |

### 9.2 开放问题

- 目标平台/市场：iOS 优先还是 Android？中国还是全球？决定 AR 可用性与回退策略。
- 当前实际生成 p95 和 GPU 型号？决定 10 秒缓冲是否保留，还是压到 3–5 秒。
- VLM 选型（云 API / 本地模型）与质量闸门阈值。
- 姿势条件 v1 用「VLM 描述 + 生成姿势参考图」是否够稳，还是需要骨架/3D proxy。
- 角色文件夹多角色/多服装的聚类策略与用户确认交互。
- 高清重拍是否进 v1，还是 Phase 2。
- 内容审核/版权条款的具体方案。
- 服务端渲染的 GPU 容量/常驻池规模与成本目标。

## 11. 里程碑与验证计划

### 11.1 Phase 0：技术 spike（4 周）

| 周 | 目标 | 产出 |
|---|---|---|
| Week 1 | 端侧真机基线 | 相机/编码/解码/显示帧时间、内存、发热 |
| Week 2 | 云端最小闭环 | 本地相机 → 上传 → 回传 → 显示；测端到端延迟/带宽 |
| Week 3 | 生成/遮挡/最终渲染 | 角色生成 p95、身份/画风/背景保真、遮挡观感 |
| Week 4 | 决策 | 继续 / 调整缓冲 / 调整架构 / 缩小 scope |

**Kill criteria**

- 中端机稳定帧率 < 24fps，或发热降频明显；
- 生成 p95 > 5s 且短期无法优化；
- 用户测试多数反馈「像贴纸」或「画风变了」；
- 单次会话成本超过目标定价的合理比例；
- 质量闸门通过率 < 70%。

### 11.2 Phase 1：MVP

- 角色文档/自动角色卡；
- AI 导演（VLM 候选 + 生成 + 遮挡 + 质检）；
- 状态机 + 双时间 UI；
- WYSIWYG 拍照 + 最终渲染 + 图片预览；
- 隐私提示、基础审核、灰度/回滚。

### 11.3 Phase 2：质量与规模

- AR 元数据、视角图集/视角重生成；
- 高清重拍、更多姿势/风格；
- 内容审核升级、成本/容量优化；
- 灰度实验与指标驱动迭代。

### 11.4 验证指标

- 离线：身份相似度、闪烁/漂移、遮挡 IoU、画风一致性、背景保真、延迟 p50/p95、内存/发热。
- 在线：会话时长、生成成功率、遮罩占比、保存率、重拍率、留存、成本/DAU。
- 用户研究：像不像站在那儿、遮挡是否自然、10s 是否可接受、双时间 UI 是否易懂。

## 12. 附录：关键术语

- **VLM**：视觉语言模型，用于场景理解、候选提案、质量打分。
- **WYSIWYG**：What You See Is What You Get；照片对应用户按下快门时看到的画面。
- **IP-Adapter**：以参考图注入身份特征的适配器；不需要微调主模型。
- **LoRA**：低秩适配；可按角色训练，提升身份一致性（可选）。
- **ControlNet**：以姿势/线稿/深度等条件约束生成。
- **Inpainting**：在指定 mask 内重绘，mask 外保持不变。
- **AO**：环境光遮蔽；用于接触阴影/边缘融合。
- **p95**：95 分位延迟/耗时；比平均值更能反映体验。
- **AI 显影**：对延迟的拟物化表达；像拍立得显影一样，把等待变成体验的一部分。
